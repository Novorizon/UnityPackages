# World 路由与结构事务

所有 API 采用主线程模型。World 仍是全局实体之上的系统执行组，不提供实体隔离。

- `World.OnUpdate` 把全部 PreUpdate / Update / PostUpdate 包在一个事务中；`finally` 排空结构命令和匹配通知。业务回调抛异常也会提交已请求命令；若提交也失败，优先保留首个异常。
- `WorldManager.IsUpdating` 在系统帧阶段或注入回调分发期间为真。此时 `Defer(Action)` 将操作加入 FIFO 命令队列；队列执行期间该标志为假，允许命令落地，重入注入回调再次启用保护。
- `BeginBatch` / `EndBatch` 可嵌套，只合并通知，不把任意用户代码变为自动回滚事务。更新前必须关闭所有批处理；否则 `World.OnUpdate` 明确抛错，避免用未提交的缓存更新。
- Add 组件的字典写入由 EntityManager 立即完成，但直到帧末/批末才匹配；Remove/Destroy 在更新阶段整体延后。同帧 Remove 再 Add 同类型仍会命中重复类型校验。
- dirty 状态按实体合并，记录首次 GUID、变更类型与 GameObject 标志。系统通过 `ISystemFilter.ComponentTypeIds` 注册到类型反向索引；多类型合并后每个相关系统只注入一次，未提供过滤器的自定义系统走全变更兼容路径。
- `NotifyEntityDestroyed` 取消该实体待投递通知，并立即全系统剔除，调用方必须先置死/清数据、再通知、最后回池。`AfterChangesApplied` 让移除组件在全部缓存解除后再回池，防止缓存引用到已复用对象。
- 逐系统/逐世界捕获投递异常并继续处理其它接收者，完成后重抛首异常。框架不能修复自定义系统主动破坏自身缓存的实现，但不会因一个钩子抛错而跳过其它正常接收者。
- 系统从池中无初始化取出，赋 World 后只初始化一次；注册与已有实体快照回填也使用事务，防止初始化/注入钩子中立即回收正在注册的对象。延迟移除携带注册代号，避免旧移除命令作用于复用后的新系统。
- Destroy 先解绑所有系统/索引/注册代号，再逐个回收；默认 World 只注册一次。退出时不重新获取已退出的 WorldManager 单例或创建对象池。

性能热路径不创建组件临时数组。非批处理的单类型通知直接查反向索引；批处理 dirty 记录和内部集合保留容量供后续复用。命令捕获闭包、集合首次扩容、注册快照仍可能分配，不宣称所有结构操作零分配。
